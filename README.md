# 剧多多文生图自动化工作台 · jdd-studio

**当前版本：v2.2.2**（版本号规则：每次更新都递增 VERSION / package.json / pyproject.toml / 本行，界面左上角自动显示）

## 一、它解决什么问题

短剧角色图/海报的生产流程原本是**纯手工体力活**：

| 环节 | 手工操作的痛 | 工作台的解法 |
|---|---|---|
| 写提示词 | 一个角色要想 6 套造型词、一份剧本要想 8 组海报词，反复打磨措辞，1~2 小时起步 | AI 提示词工程：角色 30~60 秒出 6 组、剧本通读后 60~90 秒出 8 组（6 亮调 2 暗调），可直接编辑 |
| 批量生成 | 每组都要手动「开角色卡 → 选模型 → 配参数 → 填词 → 点生成」，6 组就是 6 轮机械重复 | 页面只开一次、参数只配一次，**投递即走**：全部提示词连续下发，不等单组结果 |
| 多角色连做 | 做完一个角色再做下一个，全程盯着等 | **单页面流水线**：A 投完立刻投 B，统一收集，taskId 精确归账，每个任务一条独立进度卡 |
| 收图 | 逐张右键另存缩略图，画质差还乱 | 网络嗅探按 OSS 路径匹配 **1088×1920 原图**，自动下载、沿用平台原始文件名、按批次归档 |
| 海报复审 | 剪映扩图后人工比对平台安全区，靠肉眼估 | 复审区自动扫描剪映导出，**🛡 安全区叠加层**按平台规范量化值（顶部裁剪 12.6% / 安全区 15.4%~78%）直接对照 |

**效率提升（量级估算）**：一批 6 组 × 4 张角色图，手工约 40+ 分钟高频操作 → 工作台约 3 分钟人工（输入描述 + 勾选保存），其余全自动；8 组海报提示词从 1~2 小时人工撰写 → 90 秒 AI 成稿；多角色连做从「串行死等」→「流水线并行」，等待时间归零。

## 二、功能全景

### 👤 功能一：角色图（选角定妆照）
自然语言描述角色 → AI 出 N 组造型提示词（2/4/6/8 组可选，面部基底六组逐字一致）→ 指定角色卡批量生成 → 画廊勾选 → 平铺保存到任意位置。

### 🎬 功能二：剧本海报
上传 .docx 剧本 → AI 通读（抓英文名、关键人物、基调）→ 8 组好莱坞质感海报提示词（严守平台封面安全区、禁多余文字、拒绝 CG 感）→ 带角色参考图批量生成 → 剪映 AI 扩图 → 安全区对照 → 采用入成品库。

### 横切能力
- **参考图双通道**：①飞书《角色候选表》xlsx 整单导入（定版列/黄底格取图，零手打）；②手动上传，视觉模型对照剧本角色表**自动识别填名**（带置信度，可改名）
- **每组张数可选**：4 张（点 1 次）/ 6 张（平台选 3 张连点 2 次），张数落库、重试沿用
- **流水线并行**：多任务同页面连续投递、统一收集、独立进度/独立取消
- **⏹ 一键终止**：秒停全部任务；进度条 + 预计剩余时间（本地平滑外推）
- **无头后台运行**：不占桌面不打断工作；场记板工序导航（步骤状态实时显示、点击直达）
- **提示词 skill 实时热读**：Cherry 技能库里的模板改了就生效，无需重启

## 三、工作流程（专业说明）

### 角色图管线
```
① 角色描述 ──LLM──▶ N 组提示词（可编辑/勾选）
        │
② 指定角色卡 + 每组张数（4=单次 / 6=3张×2次）
        │
③ Playwright 无头 Chrome：打开流程页 → 项目资产 → 搜索打开指定角色卡
   → 选模型 Gpt-Image-2 → 配参数（9:16 2K / 标准）→ 循环「填词→生成」
   （submit 接口嗅探拿 taskIds，按钮就绪才投下一组）
        │
④ 收集：页面内 fetch images API（x-access-token + x-version 头）
   按 taskId 精确归组 → 全失败组宽限复验 3 轮 → 停滞/超时分级兜底
   → OSS 原图下载（沿用平台文件名）→ candidates/<任务id>/
        │
⑤ 画廊挑选（默认折叠清单视图）→ 💾 平铺保存 / 🔁 原词再生 / ✏️ 改词再生
```

### 剧本海报管线
```
① 剧本.docx ──解析（段落+表格，截断 2 万字）──▶ LLM 通读
   ──▶ 8 组海报提示词（6 亮调 2 暗调，安全区硬约束写进提示词）
   ──▶ 同步抽取「角色表」（姓名/性别/年龄/外貌）缓存 refs/roster.json
        │
② 角色参考图（双通道，编号即提示词里的「参考图片N」）
   方式一：单张上传（名字可留空，视觉模型对照角色表自动识别填名）
   方式二：飞书候选表 xlsx 整单导入（定版列/黄底格，替换式）
        │
③ 批量生成：每组只上传该组实际引用的参考图并自动重编号
   （人物与图片精确对应；没参考图的角色由 AI 按文字发挥）
        │
④ 复审闭环：勾选不满意图 → 🔧 送去扩图（review_pending/ + 拉起剪映）
   → 剪映「画面 → 基础 → AI 扩展」→ 导出 review_done/（自动扫描出现）
   → 🛡 安全区叠加对照 → ✅ 采用入成品库 / 🗑 删除 / ↩️ 撤回
```

### 关键工程设计
- **投递即走（dispatch-and-collect）**：生成等待不阻塞投递；收集按平台 taskId 归账，天然支持多任务混跑不串图
- **单页面流水线**：多任务共享一个页面与登录态，切角色只点左栏名单；取消共享页面上的任务不影响其他任务
- **双信号投递**：submit 接口确认（带 taskIds）+ 按钮就绪双确认，杜绝"点了没反应"
- **失败诊断**：平台失败原因（errorMsg/errorCode）落 server.log；全失败组连续 3 轮复验才盖棺（平台偶发先报失败后出图）
- **SSE 实时进度** + 本地每秒平滑外推 ETA；页面刷新后进度不断档
- **每次启动自动清空参考图 + 角色表**：与剧本同步归零，杜绝旧剧数据污染新剧识别

## 四、技术架构

| 模块 | 职责 |
|---|---|
| `app/main.py` | FastAPI 路由 + 流水线调度器（攒批入队）+ SSE 广播 + 进度外推 |
| `app/pipeline.py` | 剧多多页面驱动：导航/投递/统一收集/下载，多任务上下文 `_JobCtx` 独立归账 |
| `app/browser.py` | Playwright + 系统 Chrome（独立 profile，默认无头） |
| `app/promptgen.py` | 提示词生成（运行时热读 skill，内置兜底模板） |
| `app/scriptdoc.py` / `app/roster.py` / `app/vision.py` | 剧本解析 / 角色表抽取 / 参考图视觉识别 |
| `app/castsheet.py` | 飞书候选表 xlsx 解析（定版列优先、黄底格兜底、图片锚点归位） |
| `app/capcut_driver.py` | 剪映联动（一期半自动；AX 全自动待联调） |
| `app/store.py` | sqlite 任务库（WAL），含旧库自动迁移 |
| `app/static/index.html` | 单文件前端：双模式工作台 + 场记板工序导航 + 多任务进度卡 |
| `工作台管家.command` | 统一入口：启动/关闭/打开页面/登录/打包/首次安装 |

技术栈：Python 3.11+（uv 管理）· FastAPI · Playwright · sqlite · 原生 JS 单页 · LLM 走 AIOnly 网关（默认 gemini-3.6-flash）· 图像模型 Gpt-Image-2（剧多多平台）。

## 五、安装与使用

**目标机器唯一前置条件：安装 Google Chrome。**

日常使用：双击 `工作台管家.command`（项目内或桌面图标），按菜单选编号：
**1 启动 / 2 关闭 / 3 打开页面 / 4 重新登录 / 5 打包安装包 / 6 首次安装**（直接回车 = 默认项）。

迁移到其他 Mac：管家菜单选 5 打包 → 桌面 `jdd-studio-<版本>.zip` 拷到目标机解压 → 双击管家自动进入首次安装向导（装环境 → 检测 Chrome → 装依赖 → 自动找 AIOnly key → 引导登录剧多多 → 放桌面图标 → 启动）。新用户通俗指南见包内 `首次使用说明.txt`。

命令行方式：

```bash
bun run setup       # 首次：安装依赖（uv 自动拉 Python）
bun run login       # 首次/登录态失效：弹出 Chrome 登录剧多多
bun run calibrate   # 页面改版后：重新校准 config.yaml 选择器
bun run start       # 启动服务 → http://127.0.0.1:8321
```

测试：`uv run --with pytest python -m pytest tests/ -q`（54 个用例）。

## 七、隐私与安全

- 剧多多登录态保存在本机独立 Chrome profile（cookie 由 macOS 钥匙串加密），**不可跨机迁移、不入库**
- AIOnly key 仅从本机 Cherry Studio 数据库**只读**读取，不写入任何文件、不随安装包外发
- 生成数据（候选图/成品/任务库/日志）全部留在本机，已通过 .gitignore 排除
