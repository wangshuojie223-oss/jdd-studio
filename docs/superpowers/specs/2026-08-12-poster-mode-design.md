# 功能2「剧本海报模式」设计文档

- 日期：2026-08-12
- 项目：jdd-studio（剧多多文生图工作台）
- 状态：已与杰确认（方案 A、资产卡入口、每组4张、剪映全自动为目标）
- 目标版本：v1.2.0（新功能，按版本规则 +0.1.0）

## 背景

工作台已有功能1「角色图」：自然语言 → N 组角色提示词 → 剧多多批量生成 → 画廊挑选 → 平铺保存。
本设计增加功能2「剧本海报」：上传剧本 Word 文档 → LLM 分析剧本 → 8 组海报提示词（6 亮调 + 2 暗调）→ 剧多多批量生成 → 画廊挑选 → 剪映 AI 扩图复审闭环。

## 已确认的决策（杰拍板）

| 决策点 | 结论 |
|---|---|
| 架构 | 方案 A：单页双模式，顶部切换「👤 角色图 / 🎬 剧本海报」 |
| 海报生成入口 | 走剧多多资产卡（与角色卡完全同一 pipeline，换卡换提示词） |
| 生成参数 | Gpt-Image-2、9:16(2k)、标准、每组 4 张，8 组共 32 张 |
| 剪映形态 | 剪映专业版（桌面 App），目标全自动 AX 驱动（二期联调） |

## 页面与交互设计（方案 A）

顶部模式切换：「👤 角色图 ｜ 🎬 剧本海报」，切换只影响 ①② 区，③画廊和状态栏共用。

### 海报模式 ① 剧本上传区
- 拖拽/点选上传 `.docx` → `POST /api/script` 解析全文（python-docx；超长截断 ~2 万字，防 token 爆炸）
- LLM 分析剧本：提取关键人物（姓名/性格/身份/人物关系）、剧情基调、**英文名**（文档没有则 LLM 起一个并在界面标注「AI 起名」，卡片可改）
- 输出 **8 组海报提示词（6 亮调 + 2 暗调）**，方案卡沿用现有机制：勾选框（默认全选）、可编辑、亮/暗调标签
- 生成按钮复用：「🚀 生成勾选方案」「⚡ 全部生成」

### 海报模式 ② 生成
- 完全复用 `run_generation_batch` 管线：选资产卡（下拉里选「海报」类卡）→ 填词 → 生成 → 抓图 → 下载
- 进度条、预计剩余时间、⏹ 终止按钮直接可用

### ③ 画廊（共用）
- generations 表新增 `kind` 列（`character` / `poster`），旧库 ALTER TABLE 迁移，默认 `character`
- 海报记录在标题行显示「🎬 海报」徽章；9:16 竖图缩略图天然契合海报

### ④ 复审区（新模块，海报模式独有）
- 画廊勾选不满意的图 →「🔧 送去扩图」→ 原图复制到 `review_pending/`（待扩图）+ 触发剪映驱动
- 驱动完成/用户导出到 `review_done/`（已扩图）→ 工作台每 5s 扫描，**原图 vs 扩后图并排对比**
- 每张可「✅ 采用」（复制进保存位置，成品库）或「↩️ 重扩」（退回 review_pending）
- 两个文件夹默认在项目内，页面可改（复用 save_dirs 登记机制）
- **「🛡 安全区」叠加开关**：按下后在海报图上叠加 CSS 按比例绘制的分区线（不加载图片、任何 9:16 图精确对齐），目检人物与标题是否越界。分区规范（杰提供的平台安全区图，按像素测量）：

| 区域 | 垂直范围（占画面高度） | 规则 |
|---|---|---|
| 🔴 顶部图片裁剪区 | 0% ~ 12.6% | 不得有任何关键元素 |
| 🟠 文案警戒线 | 12.6% ~ 15.4% | 文案不得超过此线 |
| 🟢 封面信息安全区 | 15.4% ~ 78% | **主要人物 + 标题必须在此区间内** |
| 🟠 数据裁剪区 | 78% ~ 87% | 不得有关键元素 |
| 🔴 底部图片裁剪区 | 87% ~ 100% | 不得有任何关键元素 |

## 提示词模板（海报版）

- 做成**第二个独立 skill 文件**：`Data/Skills/film-poster-prompter/SKILL.md`，与角色 skill 同机制——`promptgen.py` 运行时实时读取、文件异常退回内置兜底副本；杰可自行维护更新，软件自动跟随
- 模板要点（来自杰的需求原文）：
  - 取剧本几个关键人物，8 组中文提示词，6 亮调 2 暗调
  - 好莱坞电影海报质感：真人质感、真实欧美人物、细腻震撼、戏剧冲突、符合剧情基调
  - 人物站位合理；体现人物性格、身份与人物关系
  - 主标题 = 剧本英文名（替换模板中的 XXXXX 占位）；醒目光效 + 符合剧本调性的装饰元素
  - 标题位置靠近画面视觉中心
  - **平台安全区硬约束（量化，来自杰提供的规范图）**：主要人物与主标题整体必须位于画面垂直方向 **15%~78%** 区间内；顶部 15% 与底部 22% 为平台裁剪/数据遮挡区，严禁放置人物头部、标题及任何关键视觉元素；垂直方向尽可能居中
  - **禁止出现主标题以外的任何文字元素**
  - 9:16 画幅
- 输出格式沿用 `### 方案一｜方向名` 分段 + `> 设计说明`，复用现有 `parse_schemes` 解析器

## 剪映驱动（app/capcut_driver.py）

- 目标交互链：打开剪映专业版 → 图片放入时间轴 → 画面-基础-AI扩展 → 扩图 → 导出到 `review_done/`
- **现实约束**：开发机上未安装剪映，macOS 辅助功能（AX）选择器必须对着真软件现场调试
- 分两期：
  - **一期（本次交付）**：驱动为半自动兜底——`send_to_expand()` 复制原图到 review_pending/、自动打开剪映、打开待扩图文件夹；用户手动扩图并导出到 review_done/；回收/对比/采用闭环完整可用
  - **二期（杰装好剪映后联调）**：用 AX 补全时间轴与 AI 扩展的自动点击；驱动接口不变，UI 零改动

## 错误处理

- docx 解析失败/非 docx → 400 中文提示
- 剧本无英文名 → LLM 起名 + 界面标注可改
- LLM 调用 → 复用现有指数退避重试（0/2/5/10s）
- 剪映未安装时点「送去扩图」→ 提示"未检测到剪映专业版，请先安装"（仍完成复制到 review_pending）
- 生成/下载/取消 → 全部复用现有管线能力

## 增补 v1.3.0：角色参考图（2026-08-12，杰补充的关键流程）

**需求**：用户上传剧本的同时提供主要角色的参考图；不是每张海报都有全部角色，提示词须按参考图加「角色名（参考图片N）」限定词，生成时人物与图片必须精确对应。

**页面探查结论（实测零消耗）**：剧多多资产生成面板支持「参考图 (0/10)」——`input[type=file]`（image/\*，multiple，set_input_files 可传）；每张缩略图带 `.ref-order-indicator` 序号角标（上传顺序=编号）和 `button.ref-delete-btn` 删除钮。

**设计**：
1. **参考图管理**（海报模式①新增区）：上传图 + 填角色名（如「杰克（男主）」），按上传顺序形成全局编号；存项目 `refs/` + `refs/refs.json` 清单；接口 GET/POST /api/refs、POST /api/refs/delete；静态挂载 /refs
2. **提示词带限定词**：/api/script 把「参考图片N=角色名」清单随剧本给 LLM；skill 模板加规则：有参考图的角色出场处必须写「角色名（参考图片N）」，无参考图的角色正常文字描述；无参考图时点分析给提示但可继续
3. **生成时逐组精确对应**（pipeline）：
   - 解析该组提示词中的「参考图片N」（正则 `参考图片?\s*(\d+)`，兼容 LLM 少写"片"字）
   - 用到的编号升序去重 → 只上传这些图 → 面板重编号为 1..k → **单趟正则把提示词编号改写为实际上传序号**（人与图永远对应）
   - 换组前逐个点 `ref-delete-btn` 清空上一组参考图
   - 编号超出已上传参考图数量 → 该组记错误跳过（宁可不生成也不出"错脸"海报）；>10 张同样报错
   - 提交生成时把当时 refs 快照存进 generations.refs 列（新列，ALTER 迁移），重试时用快照而非当前清单
4. **工具函数**（promptgen.py）：`extract_ref_numbers(prompt) -> list[int]`、`remap_refs(prompt) -> tuple[str, dict]`
